System Architecture: 10 Core Architectural Layers

Strict Two-Role Multi-Tenant Modular Monolith with separate database schemas per tenant and tenant-isolated operations.

Solid = Synchronous | Dashed = Asynchronous
Enforced Security Boundary
USER → TENANT → ROLE (HOD / Faculty) → PERMISSION → TENANT-SCOPED OPERATION → TENANT-ISOLATED SCHEMA
group 1. USERS / CLIENTS (Strictly Two Application Roles) CLIENT LAYER
admin_panel_settings ROLE 1: HOD (Department Administrator & Final Authority)

Approves faculty accounts, gives final approval for event reports & MoMs, manages calendar, views department analytics.

person ROLE 2: FACULTY / TEACHER (Operational User)

Registers (awaits HOD approval), creates events (Workshops, Seminars, Guest Lectures, Competitions, Industrial Visits), auto-generates reports, creates MoMs, and resubmits if rejected.

  • • Internet → DNS (Cloudflare) → CDN
  • • WAF (DDoS & Threat Protection)
  • • TLS/HTTPS Termination (TLS 1.3)
  • • API Gateway / Load Balancer (Rate Limiting)

  • • Spring Security + JWT Authentication

  • • Faculty Registration Workflow (PENDING_HOD_APPROVAL)
  • • Strict 2-Role Context Enforcement (HOD vs Faculty)
