## 3. Data Model & Non-Functional Requirements — MET SCMS PRD §14, §12

### High-Level Data Model (JSON store collections)

| Entity | Purpose | Lifecycle |
|--------|---------|-----------|
| users | Auth identity + role + profile | HOD-managed; user self-service for permitted fields |
| events | Core activity record | Faculty creates; draft → submitted → approved/rejected → archived |
| reports | Generated event-document representation | Derived from Event; workflow-controlled; immutable once approved |
| meetings | Source record for MoM | Faculty creates; history retained |
| moms | Generated meeting-document representation | Derived from Meeting |
| approvals | Review decision/history | Linked to Report; HOD action |
| calendarEntries | Annual academic activity | HOD-managed; may link to Event/Meeting |
| reminders | 7-day anniversary reminder | Derived from Event; read/dismiss lifecycle |
| notifications | In-app status/reminder messages | Generated by workflow/reminder engine |
| attachments | Photo/supporting document metadata | Linked to Event/report |
| auditLog | Traceability of important actions | System-generated; append-only |
| templates | Predefined report/MoM formats | HOD-managed |

### Key relationships
`User → Event → Report → Approval → Document`
`User → Meeting → MoM → Document`
`Event → Historical Reminder`
`Calendar Entry → Event/Meeting`

### Store safety rules
- Atomic writes: write to temp file then rename
- Single write queue (no concurrent writes to same collection)
- `schemaVersion` field on every collection root
- Migration function runs on startup if version is old
- `db.json` must continue to load after migration

### Non-Functional Requirements
| ID | Category | Requirement | Target |
|----|----------|-------------|--------|
| NFR-PERF-01 | Performance | Common authenticated screens load promptly | p95 ≤ 2.5 sec (excl. doc generation) |
| NFR-PERF-02 | Doc generation | Report/MoM generation completes in practical wait | p95 ≤ 10 sec |
| NFR-SEC-01 | Security | Server-side RBAC enforced on every protected action | 100% denied without permission |
| NFR-SEC-02 | Security | Passwords never stored plaintext | bcryptjs; never logged/returned |
| NFR-REL-01 | Reliability | Failed doc generation must not corrupt source records | Source record remains retrievable and retryable |
| NFR-AVAIL-01 | Availability | Departmental uptime | ≥99.5% monthly excl. planned maintenance |
| NFR-ACC-01 | Accessibility | Core flows keyboard usable; labels/errors understandable | WCAG 2.1 AA-oriented |
| NFR-COMP-01 | Compatibility | Responsive UI on desktop/tablet/mobile | Chrome/Edge/Firefox + agreed mobile browsers |
| NFR-DATA-01 | Backup | Persistent records have recoverable backups | Frequency/RPO/RTO per infra approval |
| NFR-OBS-01 | Observability | Critical failures logged | Timestamp, action, object, safe diagnostic context |
| NFR-PRIV-01 | Privacy | Collect only data required for defined workflows | Student PII not required; participation count sufficient |
| NFR-DOC-01 | Document quality | Exports avoid text overlap, truncation, malformed files | QA validation on representative templates |

### npm scripts required
- `npm run seed` — seed demo data
- `npm run reset` — reset store to empty + re-seed
- `npm test` — run all tests
- `npm run verify` — end-to-end smoke test (login + one request per feature)
